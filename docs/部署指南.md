# H3Gateway 部署指南

本文是**从零开始**的部署流程：拉取仓库 → 配置 → 启动 → 初始化 → 验证 → 升级与备份。

- 项目概览、接口文档、配置项含义见 [README](../README.md)
- 交付时的构建与实测记录见 [部署与验证](部署与验证.md)
- 上游接口细节见 [上游接口分析](上游接口分析.md)

> 下文所有命令默认在**仓库根目录**执行。仓库地址：
> <https://github.com/yhw5231/H3Gateway.git>

---

## 0. 前置条件

| 项目 | 要求 | 说明 |
| --- | --- | --- |
| Docker Engine | 20.10+ | 推荐路径（方式一 / 方式二） |
| Docker Compose | **v2.24+** | `docker-compose.yml` 使用了 `env_file: {path, required}` 语法 |
| Go | **1.23+** | 仅本地二进制（方式三）与 systemd（方式四）需要 |
| 出网 | 可访问 `https://siftq.com:443` | 网关需要直连上游 |
| 端口 | 宿主机 `8787` 空闲 | 可用 `H3_PORT` 改成别的对外端口 |
| 磁盘 | 镜像约 26 MB；数据卷按任务量增长 | 每个成品视频约 1 MB，另加输入原图 |

第三方依赖为零：`go build` 不需要联网拉包，镜像构建也不需要 `go mod download`。



## 2. 准备配置

```bash
cp .env.example .env
```

`.env.example` 里每一项都有中文注释。**首次部署至少要确认这几项**：

| 变量 | 默认 | 建议 |
| --- | --- | --- |
| `GATEWAY_ADMIN_PASSWORD` | `admin` | 改成强口令；保持 `admin` 会被强制要求首次登录后改密 |
| `H3_PORT` | `8787` | 宿主机对外端口；被占用时改这里 |
| `GATEWAY_XFF_MODE` | `auto` | 保持 `auto`，实测通过后会自动升级为 `mixed` |
| `GATEWAY_XFF_POOL` | `public` | 不想让伪造地址指向真实站点时改 `reserved`（RFC 5737 / 3849 文档段） |
| `TZ` | `Asia/Shanghai` | 控制台与日志时区 |
| `GATEWAY_PUBLIC_URL` | 空 | 放在反向代理后面时填对外地址，下载链接才正确 |

两条容易踩的规则：

1. **环境变量只在首次启动（数据文件尚不存在）时决定初始值。** 之后以数据文件里的
   设置为准，请在后台「运行设置」里修改。
2. **容器内监听端口必须保持 `8787`。** `docker-compose.yml` 的端口映射与镜像的
   `HEALTHCHECK` 都指向它；改对外端口请改 `H3_PORT`（compose）或 `-p`（docker run）。

`.env` 已被 `.gitignore` 忽略（可能含密钥），不要提交到仓库。

## 3. 启动

### 方式一：Docker Compose（推荐）

```bash
docker compose up -d --build
```

```bash
docker compose ps                  # STATUS 最终应为 (healthy)
docker compose logs -f h3gateway   # 观察启动日志
```

日志里出现下面两行即为正常：

```
level=INFO msg="h3gateway starting" version=... listen=0.0.0.0:8787 data_dir=/data ...
level=INFO msg="admin console ready" url=http://127.0.0.1:8787/admin user=admin
```

健康检查：

```bash
curl -s http://127.0.0.1:8787/healthz
# {"status":"ok","time":"..."}
```

**网络约束自检**（本项目只使用默认 bridge，不创建项目网络）：

```bash
docker inspect h3gateway --format '{{.HostConfig.NetworkMode}}'   # 期望输出 bridge
docker network ls | grep -i h3gateway                             # 期望无输出
```

常用命令：

```bash
docker compose restart          # 重启
docker compose down             # 停止（数据卷保留）
docker compose down -v          # 停止并删除数据卷（清空全部状态）
```

### 方式二：docker run

```bash
docker build --build-arg VERSION=0.1.0 -t h3gateway:latest .

docker run -d --name h3gateway \
  --network bridge \
  -p 8787:8787 \
  --env-file .env \
  -v h3gateway-data:/data \
  --restart unless-stopped \
  h3gateway:latest
```

- `.env` 里的 `GATEWAY_HOST=0.0.0.0`、`GATEWAY_PORT=8787`、`GATEWAY_DATA_DIR=/data`
  已经是容器内的正确取值，可直接用 `--env-file`；`H3_*` 是 compose 专用变量，
  传进来也无副作用。
- 用**命名卷**（`-v h3gateway-data:/data`）时 Docker 会自动沿用镜像里 `/data` 的属主，
  无需干预。
- 用**绑定挂载**（`-v /host/data:/data`）时，容器以非 root 的 uid/gid `10001` 运行，
  宿主机目录必须先授权，否则无法写入任务与视频：

  ```bash
  sudo mkdir -p /host/data && sudo chown 10001:10001 /host/data
  ```

### 方式三：本地二进制

```bash
go build -o h3gateway .
./h3gateway serve                        # 默认 127.0.0.1:8787
./h3gateway serve -host 0.0.0.0 -port 9000
./h3gateway version
```

需要环境变量时从 `.env` 导入（程序自身不解析 `.env` 文件，只读环境变量），但注意
`.env.example` 里的 `GATEWAY_DATA_DIR=/data` 是给容器用的，非容器部署必须在导入
**之后**覆盖成可写目录：

```bash
set -a; . ./.env; set +a                  # 先导入 .env
export GATEWAY_DATA_DIR="$PWD/data"       # 再覆盖为本地可写路径
./h3gateway serve
```

Windows 下产物是 `h3gateway.exe`，同样支持 `serve` / `probe` / `version`。

### 方式四：systemd（Linux 非容器部署）

先交叉编译 Linux 二进制（在仓库根目录执行）：

```bash
CGO_ENABLED=0 GOOS=linux GOARCH=amd64 \
  go build -trimpath -ldflags="-s -w -X main.version=$(git describe --tags --always)" \
  -o h3gateway .
```

再安装用户、二进制、数据目录与单元文件：

```bash
sudo useradd --system --home /var/lib/h3gateway --shell /usr/sbin/nologin h3gateway
sudo install -m 0755 h3gateway /usr/local/bin/h3gateway
sudo install -d -o h3gateway -g h3gateway -m 0750 /var/lib/h3gateway
sudo install -d -m 0755 /etc/h3gateway
sudo install -m 0640 -o root -g h3gateway .env.example /etc/h3gateway/h3gateway.env
sudo install -m 0644 deploy/h3gateway.service /etc/systemd/system/h3gateway.service
sudo systemctl daemon-reload && sudo systemctl enable --now h3gateway
```

```bash
systemctl status h3gateway
journalctl -u h3gateway -f
```

单元文件 [`deploy/h3gateway.service`](../deploy/h3gateway.service) 的要点：

- 默认只监听 `127.0.0.1`。要对外提供服务，请在
  `/etc/h3gateway/h3gateway.env` 里设 `GATEWAY_HOST=0.0.0.0`，
  并确认前面有反向代理或防火墙。
- 启用了 `ProtectSystem=strict`、`NoNewPrivileges`、`MemoryDenyWriteExecute` 等加固项，
  **唯一可写路径是 `/var/lib/h3gateway`**；数据目录请留在那里。
- 改完 `/etc/h3gateway/h3gateway.env` 需要 `systemctl restart h3gateway`
  （程序只处理 SIGINT/SIGTERM，故意没有 `ExecReload`）。后台「运行设置」里的改动
  是持久化且实时生效的，不需要重启。

### 自检命令

```bash
./h3gateway version                     # 版本号
./h3gateway help                        # 用法
./h3gateway probe -dry-run              # 只检查连通性，不消耗额度
./h3gateway probe                       # 实测 IPv4/IPv6 配额键（会消耗生成额度）
```

容器内调用：

```bash
docker exec h3gateway /usr/local/bin/h3gateway probe
```

## 4. 首次初始化（必做）

打开 <http://127.0.0.1:8787/admin>，用 **admin / admin** 登录，然后按顺序完成：

1. **修改密码**：用默认密码登录后，服务端会拒绝除改密和会话查询以外的所有后台接口
   （返回 `403`），控制台顶部有红色提示。新密码至少 8 位，改完自动换发会话。
2. **新建 API 密钥**：「API 密钥」页 → 新建（可设有效期与限速）。
   创建后会弹出完整密钥，点「复制」即可；之后在密钥列表里点「显示」仍可查看明文，
   点「复制」可直接复制（明文按需单独拉取，日志会记录 `api key revealed`）。
3. **开启强制鉴权**：「运行设置 → 访问控制」里开启强制校验。
   ⚠️ `/v1/*` 默认是**开放**的（只要能访问端口就能调用），启动日志里会有 `WARN` 提示；
   生产环境必须完成第 2、3 步。
4. **实测 XFF 配额键**：「XFF / IPv6 测试」页一键实测，或执行 `h3gateway probe`。
   通过后可将 XFF 模式切到「随机公网 IPv6」或「混合」，保持 `auto` 也会自动升级为
   `mixed`。`probe -dry-run` 只做连通性检查，**不会**给出配额键结论。
5. **确认上游连通与额度**：仪表盘 →「探测上游」，能看到 `remaining` 即正常。

> 播种逻辑：只有当数据文件里还不存在该账号时，才用 `GATEWAY_ADMIN_USER` /
> `GATEWAY_ADMIN_PASSWORD` 创建。**改过密码之后，环境变量里的默认值不会再把它改回来。**

## 5. 部署后验证

### 5.1 基础接口

```bash
curl -s http://127.0.0.1:8787/healthz                    # 200 ok
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:8787/admin
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:8787/admin/admin.js
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:8787/v1/models
```

| 场景 | 期望 |
| --- | --- |
| `/healthz` | `200` |
| `/admin`、`/admin/admin.js`、`/admin/admin.css` | `200`，且类型分别是 HTML / JS / CSS |
| `/admin/nope.js` | `404`（缺失资源不应返回 HTML 外壳） |
| `/v1/models` 未开启强制鉴权、且无启用密钥 | `200` |
| `/v1/models` 已开启强制鉴权或存在启用密钥 | 无密钥 `401`，正确密钥 `200`，错误密钥 `401` |

### 5.2 端到端生成一条视频

准备任意 JPG/PNG/WEBP 图片：

```bash
# 1) 提交
curl -X POST http://127.0.0.1:8787/v1/videos \
  -H "Authorization: Bearer <你的密钥>" \
  -F "image=@photo.jpg;type=image/jpeg" \
  -F "duration=6"
# → 202，记下返回的 id

# 2) 轮询（queued → running → succeeded，上游排队可能十几分钟）
curl -s http://127.0.0.1:8787/v1/videos/<id> -H "Authorization: Bearer <你的密钥>"

# 3) 下载成品
curl -s -o out.mp4 -D- \
  http://127.0.0.1:8787/v1/videos/<id>/content \
  -H "Authorization: Bearer <你的密钥>"
# Content-Type: video/mp4
```

生成的视频会立即缓存到 `<数据目录>/videos/<id>.mp4`，即使上游回收任务也仍可下载。
任务详情里的 `forged_ip` / `ip_family` 字段可以确认伪造的 XFF 是否生效。

## 6. 反向代理

在 nginx / Caddy 后面时，除了反代本身，还要在 `.env` 或后台设置里配置：

| 变量 | 值 | 作用 |
| --- | --- | --- |
| `GATEWAY_PUBLIC_URL` | `https://gateway.example.com` | 让返回的下载链接指向对外地址 |
| `GATEWAY_TRUST_PROXY` | `true` | 控制台记录的客户端 IP 取自 `X-Forwarded-For` |

**nginx：**

```nginx
server {
    listen 443 ssl;
    server_name gateway.example.com;
    # ssl_certificate     /etc/ssl/gateway.crt;
    # ssl_certificate_key /etc/ssl/gateway.key;

    client_max_body_size 25m;          # 输入图片上限默认 20 MB

    location / {
        proxy_pass http://127.0.0.1:8787;
        proxy_set_header Host              $host;
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 300s;       # 轮询与上传可能较慢
    }
}
```

**Caddy：**

```
gateway.example.com {
    reverse_proxy 127.0.0.1:8787
    request_body {
        max_size 25MB
    }
}
```

> 网关发往**上游**的 `X-Forwarded-For` 是它自己伪造的随机地址，与反向代理无关；
> 配置了 `PROXY_LIST` 时则完全不伪造（真实出口由代理决定）。

## 7. 升级

数据（任务、密钥、设置、视频缓存）全部在数据卷 / 数据目录里，**升级不会丢数据**。

**容器（compose）：**

```bash
cd H3Gateway
git pull
docker compose up -d --build
docker compose logs -f h3gateway
```

**容器（docker run）：** 重新 `docker build` 后 `docker rm -f h3gateway` 再按方式二启动，
数据卷沿用原来的 `h3gateway-data` 即可。

**systemd：**

```bash
git pull
CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -trimpath -ldflags="-s -w -X main.version=$(git describe --tags --always)" -o h3gateway .
sudo install -m 0755 h3gateway /usr/local/bin/h3gateway
sudo systemctl restart h3gateway
```

升级后确认版本：

```bash
docker exec h3gateway /usr/local/bin/h3gateway version
# 或后台「账号安全」页查看
```

## 8. 备份、恢复与卸载

**备份数据卷：**

```bash
docker run --rm \
  -v h3gateway-data:/data \
  -v "$PWD:/backup" \
  alpine tar czf /backup/h3-data-$(date +%F).tar.gz -C /data .
```

**恢复：**

```bash
docker compose down
docker run --rm \
  -v h3gateway-data:/data \
  -v "$PWD:/backup" \
  alpine sh -c 'rm -rf /data/* && tar xzf /backup/h3-data-YYYY-MM-DD.tar.gz -C /data'
docker compose up -d
```

**卸载：**

```bash
docker compose down        # 停止容器，保留数据卷
docker compose down -v     # 连同数据卷一起删除（清空全部状态）
```

**忘记后台密码：** 删除数据文件里的 `users` 字段（或整个 `h3gateway.json`）后重启，
会重新按环境变量播种 —— 注意这也会一并丢掉任务与密钥。

## 9. 故障排查

| 现象 | 原因与处理 |
| --- | --- |
| 容器反复重启，日志提示无法写入 | 绑定挂载的宿主机目录属主不对 → `sudo chown 10001:10001 /host/data` |
| 启动报端口占用 | 宿主机 `8787` 被占 → 改 `H3_PORT` 或 `-p`；**不要改容器内的 `8787`** |
| `/v1/*` 返回 `401`，但没配密钥 | 数据里已存在**已启用**的密钥，此时接口自动要求鉴权；到「API 密钥」新建一个 |
| 后台登录后一直提示改密码 | 默认密码必须改；忘记密码见上一节 |
| 任务长时间停在 `queued` / `running` | 上游排队可能十几分钟，任务在后台异步执行；超过 `submit_timeout_sec` 会判失败 |
| 成片与上传的图不符（约 3.5s 后画面变成别人） | 走的是 `plain` 通道 → 把 `GATEWAY_ENDPOINT_MODE` 设为 `showcase`（本版默认；旧的 `plain` 会在升级时自动迁移）。详见 [`部署与验证.md`](部署与验证.md) 第 10 节 |
| 上游返回 `401 login_required` | 该身份被单独拦截；网关会换身份重投，连续多次才失败。若持续出现，说明上游再次收紧 `showcase` 通道，可临时切 `GATEWAY_ENDPOINT_MODE=plain` 应急（成片会脱离首帧图） |
| 失败提示 `Only JPG, PNG, or WEBP images are supported` | 输入图片格式不被上游接受；确认传的确实是 JPG/PNG/WEBP |
| 改了 `.env` 但没生效 | 环境变量只在首次启动（数据文件不存在）时生效；请在后台改，或删除数据文件重来 |
| 容器时间不对 | 设置 `TZ`（compose 默认 `Asia/Shanghai`） |
| Docker Desktop（Windows/macOS）里连不上宿主机代理 | 容器无法通过 `172.17.0.1` 访问宿主机服务，改用 `host.docker.internal:<端口>`，或 `network_mode: "container:<代理容器名>"` |
| 视频下载 `404` | 只有 `succeeded` 的任务才有内容；失败任务请看 `failure_reason` |
| 想让上游配额更安全 | `GATEWAY_XFF_POOL=reserved`，使用 RFC 5737 / 3849 文档地址段 |

更多问答见 [README 的「常见问题」](../README.md#常见问题)。

## 10. 一键复现（容器路径）

```bash
# 1) 拉取
git clone https://github.com/yhw5231/H3Gateway.git && cd H3Gateway

# 2) 配置
cp .env.example .env          # 按需修改，尤其是 GATEWAY_ADMIN_PASSWORD

# 3) 启动
docker compose up -d --build

# 4) 等待健康
docker compose ps             # STATUS 应为 (healthy)
curl -s http://127.0.0.1:8787/healthz

# 5) 网络约束自检
docker inspect h3gateway --format '{{.HostConfig.NetworkMode}}'   # bridge
docker network ls | grep -i h3gateway                             # 无输出

# 6) 初始化
#    浏览器打开 http://127.0.0.1:8787/admin ，admin / admin 登录 → 改密 → 建密钥 → 开强制鉴权

# 7) 上游实测（可选，会消耗额度）
docker exec h3gateway /usr/local/bin/h3gateway probe
```
